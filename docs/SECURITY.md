# Security Model

## Threat model

NUDL source files, workspace files, imported datasets, generated code, and packages may be untrusted. The compiler should be safe to run on ordinary source files without executing them during parsing or code generation.

## Required safeguards

- Bound source-file size, token count, AST depth, array sizes, and interpreter steps.
- Avoid shelling out to generated code or native compilers unless the user explicitly requests a separate build step.
- Escape strings correctly for every output language.
- Do not interpolate untrusted values into shell commands or SQL.
- Make filesystem writes explicit and report failures.
- Reject malformed workspace paths, duplicate paths, and unsupported workspace schema versions.
- Keep secrets and API keys out of source files and client-side bundles.
- Document any network access performed by optional IDE integrations.
- Avoid executing imported data as code.

## Browser IDE

Browser execution should run in the bundled interpreter with execution limits. Generated source code is downloadable text; it is not sandboxed merely because it was generated by the IDE. Users must review generated code before compiling or executing it.

## Reporting

Please report security issues privately to the repository maintainer rather than publishing an exploit before a fix is available. Do not include real credentials, personal data, or proprietary source in public issue reports.
